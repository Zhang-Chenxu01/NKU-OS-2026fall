## 1. exception_handler

**Pre-Condition**：

**Post-Condition**：

## 2. syscall

**Pre-Condition**：

**Post-Condition**：

- 对于正常返回的系统调用，返回值写入用户可见的返回寄存器。

**Case 1：合法系统调用**

- 返回值按照用户态 ABI 写回。

## 3. sys_exit / sys_fork / sys_wait / sys_exec

**Pre-Condition**：

- 系统调用参数已由 `syscall()` 获取。
- 当前进程及相关进程管理接口处于有效状态。

**Post-Condition**：

- 对应操作正确转交内核进程管理层。
- 参数及返回值符合用户态接口语义。
- 进程上下文及资源状态保持一致。

**Case 1：sys_exit**

调用现有退出接口，传递退出码。成功退出后当前进程不应继续执行原用户程序。

**Case 2：sys_fork**

调用现有进程创建接口，正确传递当前执行上下文及所需参数。保证调用约定支持父进程获得子 PID、子进程获得 0 的语义。

**Case 3：sys_wait**

传递目标 PID 和退出码存储地址，处理合法等待请求。对非空用户指针进行必要的地址及写权限检查，遵循底层接口的内存访问约定。

**Case 4：sys_exec**

正确传递程序名称、长度、二进制地址及大小等实际接口要求的参数。检查用户地址、长度及访问权限，避免非法用户指针导致内核异常。

**Requirements**：

- 考虑 `fork` 返回值、`exec` 成功后的上下文变化及 `exit` 不返回等特殊情况。

## 4. sys_yield / sys_kill / sys_getpid

**Pre-Condition**：

- 当前进程及所需进程管理接口有效。

**Post-Condition**：

- 系统调用请求正确转交对应内核接口。

**Case 1：sys_yield**

请求当前进程主动让出 CPU，正确处理对应接口的返回语义。

**Case 2：sys_kill**

传递目标 PID，正确处理合法进程、无效 PID、目标不存在等情况，具体错误码遵循已有进程管理接口。

**Case 3：sys_getpid**

返回当前进程 PID，不修改进程状态。

## 5. sys_putc / sys_pgdir

**Post-Condition**：

## copy_range

**Pre-Condition**：

- `to` 和 `from` 指向有效的目标及源页表。
- `[start, end)` 为待复制的合法虚拟地址区间，满足工程的页对齐和地址范围约定。
- 物理内存管理器和页表管理功能已初始化。

**Post-Condition**：

- 目标地址空间包含源地址空间在指定范围内需要复制的有效页面。
- 普通 fork 模式下，源页面与目标页面内容相同，但使用独立物理页。
- 页面权限、页表映射和引用计数正确。
- 复制过程不修改父进程原有页面内容。
- 失败时正确释放本函数仍负责的资源，并返回合理错误码。

**Case 1：源页面有效**

当源地址存在有效的普通叶子映射时：

- 查找对应源物理页。
- 分配目标物理页。
- 将源页面内容完整复制到目标页面。
- 按原有用户访问权限建立目标映射。
- 保证父子进程后续修改各自页面时互不影响。

**Case 2：源页面不存在**

当虚拟地址对应的源页表项不存在或尚未映射物理页时，跳过相应区域，不为无效映射额外分配数据页面。

应根据实际 Sv39 页表结构判断可安全跳过的范围，避免遗漏后续有效页面。

**Case 3：页面分配或映射失败**

当分配目标物理页、创建目标页表项或建立映射失败时：

- 返回工程约定的错误码。
- 释放尚未移交给目标页表管理的临时资源。
- 避免重复释放、引用计数错误和新增页面泄漏。
- 明确已成功建立的目标映射由哪一层负责回滚，保持与 `dup_mmap`、`copy_mm` 的资源管理契约一致。

**Case 4：异常参数或特殊页表映射**

检查空区间、地址未对齐、范围越界及目标已经存在映射等边界情况，按现有接口约定处理。

特别注意 Lab4 使用的 Sv39 大页映射。不能将上层叶子页表项误认为下一级页表指针；若当前函数不支持相关情形，应遵循现有页表接口约定安全处理。

**Requirements**：

1. 保证物理页分配、映射和释放的引用计数语义一致。
2. 正确保留用户页面的权限，避免错误赋予额外读写或执行权限。
3. 不覆盖父进程原有页表映射。
4. 不修改现有的页表层级和内存布局设计。
5. 若发现底层 `get_pte` 等接口已有独立缺陷，不擅自扩大修改范围；记录其对本函数的影响及必要的后续处理。
